FasdeqOS Documentation & Wiki

An open-source rolling-release Linux distribution combining the pure power of Arch Linux with the intuitive, clean filesystem layout of Apple macOS.

ID: fasdeqos Type: Rolling Release Base: Arch Linux + Linux Kernel Filesystem: Btrfs (APFS model)

Chapter 1 — Introduction & Architecture

FasdeqOS is an independent, open-source Linux operating system built directly on top of Arch Linux. It is designed to provide a frictionless transition from macOS to the Linux ecosystem by replicating the clean, human-readable filesystem tree of macOS while keeping the bleeding-edge upstream Linux Kernel, hardware drivers, and systemd service foundation.

Filesystem Layout

Traditional Linux distributions place binaries and files across sprawling directories (/usr/bin, /etc, /var/lib, /lib64). FasdeqOS solves this by leveraging Btrfs subvolumes to emulate the clean hierarchy of Apple APFS:

DirectorySubvolume RoleDescription
/ApplicationsApplicationsUser software packages, self-contained app bundles, icons, binaries, and dependencies.
/SystemSystemImmutable operating system root volume containing core system binaries, libraries, and essential daemons.
/LibraryLibraryGlobal settings, frameworks, shared system resources, desktop themes, and global configurations.
/UsersUsersUser accounts, personal data, caches, documents, and personal home directories (e.g. /Users/fasdeq).
/VolumesVolumesMount points for external USB media, secondary disk drives, and network storage shares.
/bootBoot volumeUEFI bootloaders (GRUB, Limine, systemd-boot) and compressed Linux kernel images.
/rootRoot HomeAdministrative home directory for the superuser.
Clean Abstraction: Legacy UNIX folders like /usr and /etc are neatly mounted behind the scenes inside private stage volumes to preserve compatibility with standard software while presenting a spotless top-level directory.

Package Management with pkg

FasdeqOS features a dedicated package manager called pkg, designed with clear BSD-inspired command syntax. Under the hood, pkg interacts with Arch's powerful pacman engine, handling user application isolation, containerization, and system customization.

CommandPurpose & Explanation
pkg install <package|file>Installs applications from repositories or local .tar.zst packages. Resource-heavy applications automatically run in isolated containers.
pkg uninstall <package>Removes installed applications and unregisters metadata.
pkg listLists all installed applications located in /Applications.
pkg search <text>Searches package repositories for available packages matching keywords.
pkg info <package>Displays comprehensive information, dependencies, and size of a package.
pkg updateRefreshes repository mirrors and package synchronization databases.
pkg upgrade [package ...]Upgrades the entire system and all installed applications.
pkg list-repoLists configured third-party and extra repositories.
pkg add-repo <url> [name]Adds a custom package repository to the system.

Troubleshooting & First Aid

  • No network inside a Virtual Machine: If testing in a virtualized environment, ensure your VM hypervisor assigns an active network adapter (VirtIO / NAT / Bridged). In QEMU, attach -net nic,model=virtio -net user. The installer runs auto-diagnostics at start.
  • USB Boot Failure: Disable Secure Boot in your UEFI/BIOS firmware settings. Flash the ISO using raw DD mode (we recommend Balena Etcher or dd if=fasdeqos.iso of=/dev/sdX bs=4M status=progress).
  • Steam & Wine compatibility: Classic Linux gaming packages expect rigid paths in /bin. FasdeqOS isolates these workloads smoothly using containers (Distrobox, Flatpak, Podman). See Chapters 4 & 5.

Chapter 2 — Installation Guide

The standard way to install FasdeqOS is through the interactive installer which launches automatically on boot. However, if you wish to customize disk layouts, build a minimal system, or manage encryption manually, follow the manual installation pipeline below.

Manual Installation Workflow

Boot the live ISO, switch to root, identify your target storage drive (replace /dev/sdX accordingly), and run:

# 1. Partition the disk (BIOS Boot, EFI System, Btrfs Root)
sgdisk --zap-all /dev/sdX
sgdisk -n1:0:+1M -t1:ef02 -n2:0:+512M -t2:ef00 -n3:0:0 -t3:8300 /dev/sdX

# 2. Format EFI and Btrfs filesystems
mkfs.fat -F32 -n EFI /dev/sdX2
mkfs.btrfs -L FasdeqOS /dev/sdX3

# 3. Create APFS-style Btrfs subvolumes
mount /dev/sdX3 /mnt
for v in root System Applications Library Users private; do
  btrfs subvolume create /mnt/$v
done
umount /mnt

# 4. Mount root with zstd compression and mount subvolumes
mount -o compress=zstd:1,subvol=root /dev/sdX3 /mnt
mkdir -p /mnt/{System,Applications,Library,Users,private,Volumes,usr,lib,lib64,etc,var,tmp}
for v in System Applications Library Users private; do
  mount -o compress=zstd:1,subvol=$v /dev/sdX3 /mnt/$v
done
mkdir -p /mnt/private/stage/boot
mount /dev/sdX2 /mnt/private/stage/boot

# 5. Bootstrap base software with pacstrap
pacstrap -K /mnt/private/stage filesystem glibc musl bash fish pacman util-linux \
  kmod systemd linux linux-firmware mkinitcpio btrfs-progs grub efibootmgr sudo mesa

After base bootstrap, enter the chroot to configure user credentials, locales, the fasdeqos-disk initramfs hook, and the bootloader:

# 6. Extract payload and reorganize into FasdeqOS structure
bsdtar -xpf fasdeqos-payload.tar.zst -C /mnt/private/stage
bsdtar -cpf - -C /mnt/private/stage/usr . | bsdtar -xpf - -C /mnt/System
rm -rf /mnt/private/stage/usr
mv /mnt/private/stage/etc /mnt/private/etc
mv /mnt/private/stage/var /mnt/private/var
mv /mnt/private/stage/root /mnt/private/var/root
rm -rf /mnt/private/stage

Chapter 3 — Migration from Arch-based Systems

If you already run an Arch Linux installation or derivative (Manjaro, Garuda, CachyOS, or experimentally Omarchy), you can migrate directly into FasdeqOS in-place without losing your personal data.

Prerequisites

  • Operating system based on Arch Linux.
  • Root filesystem formatted as Btrfs.
  • UEFI system with Limine, GRUB, or systemd-boot.
  • Root privileges.

Reflink Cloning Technology

Missing Btrfs subvolumes are created on the existing partition. Files are cloned using Btrfs reflink technology, meaning duplicate data references existing blocks without consuming extra storage space.

Migration ModeBehavior
Without backup (Recommended)GNU coreutils are replaced by BSD chimerautils, desktop apps and games migrate to /Applications, pacman is replaced by pkg, and the legacy system is removed after the first verified boot.
With backupData is duplicated into /Users and the new layout while retaining the entire legacy distribution intact.

Running the Migration Script

Open your terminal and run:

curl -fsSL https://raw.githubusercontent.com/Fasdeq13/fasdeqOS/main/fasdeqos-migrate -o fasdeqos-migrate
sudo -E bash fasdeqos-migrate

Inspect the script directly on GitHub. Select your preferences in the interactive wizard and reboot when finished.

Chapter 4 — Steam & Gaming

Steam and 32-bit gaming dependencies expect traditional Unix hierarchies in /bin. FasdeqOS keeps its host clean and isolates Steam within an optimized Distrobox container running the performant CachyOS userland.

Step 1. Container Creation

Depending on your graphics hardware, run the appropriate container creation command:

For NVIDIA GPUs:

distrobox create -i docker.io/cachyos/cachyos-v3:latest -n cachy-steam \
  --nvidia --additional-flags-create "--device /dev/nvidiactl --device /dev/nvidia-uvm --device /dev/nvidia0 -v /Users:/Users"

For AMD / Intel GPUs:

distrobox create -i docker.io/cachyos/cachyos-v3:latest -n cachy-steam \
  --additional-flags-create "--device /dev/dri -v /Users:/Users:rslave"

Step 2. Entering Container & Installing Steam

# Enter the container
distrobox enter cachy-steam

# Inside the container: update and install Steam
sudo pacman -Syu steam

Step 3. Exporting Steam to the Host

# Inside container: export Steam to host application menus
distrobox-export --app steam

Steam will now appear in your application launcher and desktop interface, running with direct GPU acceleration.

Chapter 5 — Wine & Windows Applications

Run Windows applications and games effortlessly by installing Wine into your cachy-steam gaming container.

Step 1. Install Wine & Runtime Libraries

Enter the container (or use the one created in Chapter 4) and execute:

distrobox enter cachy-steam
sudo pacman -Syu wine winetricks wine-mono wine-gecko lib32-gnutls --noconfirm

Step 2. Export Wine Binaries to Host User PATH

distrobox-export --bin /usr/bin/wine --export-path ~/.local/bin
distrobox-export --bin /usr/bin/winecfg --export-path ~/.local/bin
distrobox-export --bin /usr/bin/winetricks --export-path ~/.local/bin

Step 3. Configure Wine Prefix

Run winecfg in your terminal to initialize and configure your ~/.wine prefix.

Step 4. Creating a Desktop Shortcut

To launch any .exe seamlessly from your desktop or app menu, create a .desktop file:

nano /Users/$USER/.local/share/applications/myapp.desktop

Paste the following desktop entry:

[Desktop Entry]
Name=My Windows Application
Exec=distrobox-enter -n cachy-steam -- wine "/path/to/program.exe"
Type=Application
Terminal=false
Categories=Game;

In nano: press Ctrl+O and Enter to save, then Ctrl+X to exit.

Документация и База Знаний FasdeqOS

Дистрибутив Linux со скользящей моделью обновлений (rolling release), объединяющий гибкость и мощь Arch Linux с удобной и понятной файловой структурой macOS.

ID: fasdeqos Тип: Rolling Release Основа: Arch Linux + Linux Kernel Файловая система: Btrfs (APFS-модель)

Глава 1 — Введение и архитектура

FasdeqOS — это открытый дистрибутив Linux на базе Arch Linux, созданный для максимально комфортного перехода с macOS на Linux. Он сохраняет официальное ядро Linux, аппаратные драйверы и systemd от Arch, но кардинально реорганизует всё, что находится выше — структуру каталогов, окружение пользователя и управление софтом.

Структура файлов

Вместо разбросанных по диску классических каталогов (/usr/bin, /etc, /var) FasdeqOS использует субтома Btrfs, имитируя файловую систему Apple APFS:

КаталогСубтом BtrfsНазначение
/ApplicationsApplicationsПапка приложений пользователя. Содержит изолированные пакеты, иконки, бинарники и зависимости.
/SystemSystemСистемный том операционной системы. Здесь находятся базовые файлы ОС и критически важные службы.
/LibraryLibraryБиблиотеки, общесистемные ресурсы, темы оформления и глобальные конфигурации.
/UsersUsersДомашние каталоги пользователей (например, /Users/fasdeq), личные документы и конфиги.
/VolumesVolumesТочки монтирования внешних накопителей, флешек, дополнительных разделов и сетевых дисков.
/bootBoot volumeЗагрузчики (GRUB, Limine, systemd-boot) и сжатые образы ядер Linux.
/rootRoot HomeДомашний каталог суперпользователя root.
Чистота и порядок: Стандартные каталоги /usr, /etc и /var скрыты и смонтированы внутри изолированных слоёв, сохраняя полную бинарную совместимость со стандартами Linux.

Пакетный менеджер pkg

В системе используется пакетный менеджер pkg, синтаксис которого вдохновлён BSD pkg. Он представляет собой удобную высокоуровневую обёртку над pacman.

КомандаОписание и возможности
pkg install <пакет|файл>Установка приложений из репозиториев или локальных файлов .tar.zst. Тяжёлые приложения автоматически изолируются в контейнерах.
pkg uninstall <пакет>Чистое удаление приложения и сопутствующих файлов.
pkg listПросмотр списка установленных приложений в /Applications.
pkg search <текст>Поиск доступных пакетов по ключевым словам.
pkg info <пакет>Подробная информация о пакете, зависимостях и размере.
pkg updateОбновление баз данных пакетов и зеркал.

pkg list-repoПросмотр списка подключённых дополнительных репозиториев.
pkg add-repo <url> [имя]Подключение стороннего репозитория.
pkg remove-repo <имя>Удаление добавленного репозитория.
pkg kernel [list|use <имя>]Просмотр доступных ядер и переключение активного ядра на лету (linux, linux-cachyos, linux-zen).
pkg sys <аргументы pacman>Прямой вызов pacman на системном томе /System. Рекомендуется только для ядер, драйверов и сервисов.
pkg change-desktop <имя>Мгновенное переключение рабочего стола. Доступны: plasma, gnome, cosmic, hyprland, niri, xfce, cinnamon, mate, lxqt.
pkg change-int <имя>Переключение системного окружения (userland) между chimerautils (утилиты BSD) и BusyBox.

Первая помощь и решение проблем

  • Нет сети в виртуальной машине: Рекомендуется использовать гипервизор QEMU/KVM с virtio-сетью либо вручную проверить наличие сетевого адаптера (Bridged/NAT) в настройках VM. Установщик при старте выводит сетевую диагностику.
  • Флешка не загружается: Отключите Secure Boot в настройках UEFI BIOS. Записывайте образ ISO строго в режиме DD (рекомендуется утилита Balena Etcher либо команда dd).
  • Зависимость Steam и Wine от /bin: Из-за жесткой привязки старых 32-битных программ к классическому /bin, в FasdeqOS используется контейнеризация (Distrobox, Flatpak, Podman). Подробнее в Главах 4 и 5.

Глава 2 — Установка системы

Для большинства пользователей рекомендуется штатный автоматический установщик, стартующий сразу при загрузке Live-образа. Ручная установка полезна тем, кто хочет собрать систему под свои задачи, настроить шифрование или получить минимальный набор софта.

Пошаговый сценарий ручной установки

Загрузитесь в live-систему под root и выполните разметку диска (замените /dev/sdX на ваш диск):

# 1. Разметка накопителя
sgdisk --zap-all /dev/sdX
sgdisk -n1:0:+1M -t1:ef02 -n2:0:+512M -t2:ef00 -n3:0:0 -t3:8300 /dev/sdX

# 2. Форматирование EFI и Btrfs
mkfs.fat -F32 -n EFI /dev/sdX2
mkfs.btrfs -L FasdeqOS /dev/sdX3

# 3. Создание субтомов в стиле APFS
mount /dev/sdX3 /mnt
for v in root System Applications Library Users private; do
  btrfs subvolume create /mnt/$v
done
umount /mnt

# 4. Монтирование томов с zstd-сжатием
mount -o compress=zstd:1,subvol=root /dev/sdX3 /mnt
mkdir -p /mnt/{System,Applications,Library,Users,private,Volumes,usr,lib,lib64,etc,var,tmp}
for v in System Applications Library Users private; do
  mount -o compress=zstd:1,subvol=$v /dev/sdX3 /mnt/$v
done
mkdir -p /mnt/private/stage/boot
mount /dev/sdX2 /mnt/private/stage/boot

# 5. Базовое развертывание пакетов через pacstrap
pacstrap -K /mnt/private/stage filesystem glibc musl bash fish pacman util-linux \
  kmod systemd linux linux-firmware mkinitcpio btrfs-progs grub efibootmgr sudo mesa

Затем выполните arch-chroot в папке stage (настройка локали, пользователей, хука initramfs fasdeqos-disk и GRUB) и переложите файлы в структуру FasdeqOS:

# 6. Распаковка пейлоада и перенос файлов
bsdtar -xpf fasdeqos-payload.tar.zst -C /mnt/private/stage
bsdtar -cpf - -C /mnt/private/stage/usr . | bsdtar -xpf - -C /mnt/System
rm -rf /mnt/private/stage/usr
mv /mnt/private/stage/etc /mnt/private/etc
mv /mnt/private/stage/var /mnt/private/var
mv /mnt/private/stage/root /mnt/private/var/root
rm -rf /mnt/private/stage

Глава 3 — Миграция с Arch-дистрибутивов

Если у вас уже установлен Arch Linux, Manjaro, Garuda, CachyOS или экспериментальный Omarchy, вы можете перенести систему в структуру FasdeqOS без потери личных данных.

Требования

  • Дистрибутив на базе Arch Linux.
  • Корневой раздел на файловой системе Btrfs.
  • Режим UEFI и один из поддерживаемых загрузчиков: Limine, GRUB или systemd-boot.
  • Права суперпользователя root.

Технология клонирования Reflink

Недостающие тома создаются в существующем пуле Btrfs. Файлы клонируются через reflink, благодаря чему миграция не требует дополнительного свободного места на диске.

РежимЧто происходит
Без бэкапа (Рекомендуется)GNU-утилиты заменяются на chimerautils, приложения и игры переезжают в /Applications, pacman заменяется на pkg, а старая система автоматически удаляется после первой успешной загрузки.
С бэкапомВсе данные копируются в /Users и новую структуру, а старая конфигурация полностью сохраняется на случай отката.

Команда для запуска скрипта

curl -fsSL https://raw.githubusercontent.com/Fasdeq13/fasdeqOS/main/fasdeqos-migrate -o fasdeqos-migrate
sudo -E bash fasdeqos-migrate

Исходный код скрипта доступен на GitHub. Выберите нужные опции в меню мастера и перезагрузитесь.

Глава 4 — Steam и игры

Для запуска Steam в изолированном, оптимизированном окружении без засорения хост-системы используется контейнер Distrobox на базе производительного образа CachyOS v3.

Шаг 1. Создание игрового контейнера

Для видеокарт NVIDIA:

distrobox create -i docker.io/cachyos/cachyos-v3:latest -n cachy-steam \
  --nvidia --additional-flags-create "--device /dev/nvidiactl --device /dev/nvidia-uvm --device /dev/nvidia0 -v /Users:/Users"

Для видеокарт AMD / Intel:

distrobox create -i docker.io/cachyos/cachyos-v3:latest -n cachy-steam \
  --additional-flags-create "--device /dev/dri -v /Users:/Users:rslave"

Шаг 2. Вход в контейнер и установка Steam

# Вход в контейнер
distrobox enter cachy-steam

# Внутри контейнера: установка Steam
sudo pacman -Syu steam

Шаг 3. Экспорт ярлыка на хост

# Внутри контейнера: экспорт в меню приложений
distrobox-export --app steam

После этого Steam появится в стандартном меню приложений и на рабочем столе хост-системы с полной поддержкой GPU-ускорения.

Глава 5 — Wine и Windows-программы

Запуск Windows-софта организуется через Wine прямо внутри созданного контейнера cachy-steam.

Шаг 1. Установка пакетов Wine в контейнере

Войдите в игровой контейнер и выполните:

distrobox enter cachy-steam
sudo pacman -Syu wine winetricks wine-mono wine-gecko lib32-gnutls --noconfirm

Шаг 2. Экспорт бинарников в PATH пользователя

distrobox-export --bin /usr/bin/wine --export-path ~/.local/bin
distrobox-export --bin /usr/bin/winecfg --export-path ~/.local/bin
distrobox-export --bin /usr/bin/winetricks --export-path ~/.local/bin

Шаг 3. Настройка префикса Wine

Для первичной инициализации префикса выполните в терминале winecfg.

Шаг 4. Создание ярлыка (.desktop) для программы

Создайте файл ярлыка в пользовательском каталоге:

nano /Users/$USER/.local/share/applications/myapp.desktop

Вставьте следующее содержимое:

[Desktop Entry]
Name=Моя Windows Программа
Exec=distrobox-enter -n cachy-steam -- wine "/path/to/program.exe"
Type=Application
Terminal=false
Categories=Game;

В редакторе nano: нажмите Ctrl+O и Enter для сохранения, затем Ctrl+X для выхода.

Manuale Ufficiale e Wiki di FasdeqOS

Distribuzione Linux rolling-release che combina la potenza e la flessibilità di Arch Linux con l'eleganza e l'intuitività della struttura file di macOS.

ID: fasdeqos Tipo: Rolling Release Base: Arch Linux + Linux Kernel File system: Btrfs (modello APFS)

Capitolo 1 — Introduzione e Architettura

FasdeqOS è un sistema operativo Linux open source basato su Arch Linux, progettato specificamente per facilitare il passaggio da macOS al mondo Linux. Mantiene intatti il Kernel Linux ufficiale, i driver hardware e systemd forniti da Arch, rivoluzionando completamente tutto il livello superiore: la gerarchia delle cartelle, lo spazio utente e la gestione del software.

Struttura del File System

Al posto delle caotiche cartelle UNIX tradizionali (/usr/bin, /etc, /var), FasdeqOS impiega i sottovolumi di Btrfs per riprodurre fedelmente la gerarchia pulita di Apple APFS:

CartellaRuolo SottovolumeDescrizione
/ApplicationsApplicationsApplicazioni utente, bundle software autonomi, icone, file binari e dipendenze.
/SystemSystemVolume di sistema contenente i file essenziali del sistema operativo e i demoni di base.
/LibraryLibraryLibrerie condivise, risorse di sistema, temi grafici e impostazioni globali.
/UsersUsersCartelle home degli utenti (es. /Users/fasdeq), file personali e configurazioni.
/VolumesVolumesPunti di montaggio per unità rimovibili USB, dischi secondari e condivisioni di rete.
/bootBoot volumeBootloader UEFI (GRUB, Limine, systemd-boot) e immagini del kernel compresse.
/rootRoot HomeCartella home dell'amministratore (superuser).
Isolamento Trasparente: Le directory legacy come /usr ed /etc sono protette e montate internamente in volumi di stage privati, garantendo piena compatibilità binaria con i programmi Linux standard.

Il gestore pkg offre una sintassi intuitiva in stile BSD, fungendo da wrapper avanzato per pacman.

Risoluzione dei Problemi

  • Assenza di rete nelle Macchine Virtuali: Verifica che la macchina virtuale abbia una scheda di rete attiva assegnata (VirtIO o NAT/Bridge). Con QEMU usa -net nic,model=virtio -net user. L'installer esegue un test diagnostico all'avvio.
  • L'unità USB non si avvia: Disattiva il Secure Boot nel BIOS/UEFI. Scrivi l'immagine ISO in modalità raw DD (consigliati Balena Etcher o il comando dd).
  • Compatibilità con Steam e Wine: Le vecchie librerie a 32 bit e i giochi dipendono fortemente dai percorsi in /bin. FasdeqOS gestisce questi carichi in container (Distrobox, Flatpak, Podman). Vedi Capitoli 4 e 5.

Capitolo 2 — Guida all'Installazione

L'installer grafico/testuale si avvia automaticamente all'avvio dell'ISO. Se desideri personalizzare le partizioni, impostare la crittografia o ottenere un'installazione minima, segui la procedura manuale sottostante.

Procedura di Installazione Manuale

Avvia il sistema live come utente root e prepara il disco (sostituisci /dev/sdX con l'identificativo del tuo disco):

# 1. Partizionamento del disco
sgdisk --zap-all /dev/sdX
sgdisk -n1:0:+1M -t1:ef02 -n2:0:+512M -t2:ef00 -n3:0:0 -t3:8300 /dev/sdX

# 2. Formattazione partizioni EFI e Btrfs
mkfs.fat -F32 -n EFI /dev/sdX2
mkfs.btrfs -L FasdeqOS /dev/sdX3

# 3. Creazione dei sottovolumi Btrfs
mount /dev/sdX3 /mnt
for v in root System Applications Library Users private; do
  btrfs subvolume create /mnt/$v
done
umount /mnt

# 4. Montaggio dei volumi con compressione zstd
mount -o compress=zstd:1,subvol=root /dev/sdX3 /mnt
mkdir -p /mnt/{System,Applications,Library,Users,private,Volumes,usr,lib,lib64,etc,var,tmp}
for v in System Applications Library Users private; do
  mount -o compress=zstd:1,subvol=$v /dev/sdX3 /mnt/$v
done
mkdir -p /mnt/private/stage/boot
mount /dev/sdX2 /mnt/private/stage/boot

# 5. Bootstrap del sistema base con pacstrap
pacstrap -K /mnt/private/stage filesystem glibc musl bash fish pacman util-linux \
  kmod systemd linux linux-firmware mkinitcpio btrfs-progs grub efibootmgr sudo mesa

Accedi a chroot nella cartella stage (imposta lingua, utenti, hook initramfs fasdeqos-disk e GRUB), quindi riorganizza i file nella struttura di FasdeqOS:

# 6. Estrazione del payload e posizionamento finale
bsdtar -xpf fasdeqos-payload.tar.zst -C /mnt/private/stage
bsdtar -cpf - -C /mnt/private/stage/usr . | bsdtar -xpf - -C /mnt/System
rm -rf /mnt/private/stage/usr
mv /mnt/private/stage/etc /mnt/private/etc
mv /mnt/private/stage/var /mnt/private/var
mv /mnt/private/stage/root /mnt/private/var/root
rm -rf /mnt/private/stage

Capitolo 3 — Migrazione da Distribuzioni Basate su Arch

Se hai già un'installazione di Arch Linux, Manjaro, Garuda, CachyOS o Omarchy (sperimentale), puoi migrare a FasdeqOS senza perdere i tuoi file personali.

Requisiti

  • Sistema basato su Arch Linux.
  • Partizione radice formattata su Btrfs.
  • Ambiente UEFI con bootloader Limine, GRUB o systemd-boot.
  • Privilegi di root.

Clonazione Istantanea Reflink

I sottovolumi mancanti vengono creati nel pool Btrfs esistente. I file vengono clonati tramite reflink Btrfs, evitando qualsiasi consumo aggiuntivo di spazio su disco.

ModalitàDettagli operazione
Senza backup (Consigliata)Le utility GNU vengono sostituite da chimerautils, app e giochi passano a /Applications, pacman viene sostituito da pkg, e il vecchio sistema viene rimosso al primo avvio riuscito.
Con backupI dati vengono duplicati in /Users e nella nuova gerarchia, lasciando intatto il vecchio sistema.

Esecuzione dello Script

curl -fsSL https://raw.githubusercontent.com/Fasdeq13/fasdeqOS/main/fasdeqos-migrate -o fasdeqos-migrate
sudo -E bash fasdeqos-migrate

Visualizza il codice su GitHub. Seleziona le impostazioni desiderate e riavvia il computer.

Capitolo 4 — Steam e Gaming

Per eseguire Steam mantenendo pulito il sistema host, utilizziamo un container Distrobox basato sull'immagine ottimizzata di CachyOS v3.

Passo 1. Creazione del Container

Per GPU NVIDIA:

distrobox create -i docker.io/cachyos/cachyos-v3:latest -n cachy-steam \
  --nvidia --additional-flags-create "--device /dev/nvidiactl --device /dev/nvidia-uvm --device /dev/nvidia0 -v /Users:/Users"

Per GPU AMD / Intel:

distrobox create -i docker.io/cachyos/cachyos-v3:latest -n cachy-steam \
  --additional-flags-create "--device /dev/dri -v /Users:/Users:rslave"

Passo 2. Accesso e Installazione di Steam

# Entra nel container
distrobox enter cachy-steam

# Installa Steam all'interno del container
sudo pacman -Syu steam

Passo 3. Esportazione dell'Applicazione

# Esporta il collegamento nell'ambiente desktop dell'host
distrobox-export --app steam

L'icona di Steam comparirà direttamente nel menu applicazioni con pieno accesso all'accelerazione grafica hardware.

Capitolo 5 — Wine e Applicazioni Windows

Esegui programmi e giochi Windows nativi tramite Wine nel container cachy-steam.

Passo 1. Installazione di Wine nel Container

distrobox enter cachy-steam
sudo pacman -Syu wine winetricks wine-mono wine-gecko lib32-gnutls --noconfirm

Passo 2. Esportazione dei Binari nel PATH Utente

distrobox-export --bin /usr/bin/wine --export-path ~/.local/bin
distrobox-export --bin /usr/bin/winecfg --export-path ~/.local/bin
distrobox-export --bin /usr/bin/winetricks --export-path ~/.local/bin

Passo 3. Inizializzazione del Prefisso Wine

Esegui winecfg nel terminale per generare il prefisso ~/.wine.

Passo 4. Creazione del File di Avvio (.desktop)

Crea il file di avvio desktop nella cartella utente:

nano /Users/$USER/.local/share/applications/myapp.desktop

Inserisci la seguente configurazione:

[Desktop Entry]
Name=La Mia Applicazione Windows
Exec=distrobox-enter -n cachy-steam -- wine "/path/to/program.exe"
Type=Application
Terminal=false
Categories=Game;

Con nano: premi Ctrl+O e Invio per salvare, poi Ctrl+X per uscire.
